# Pilot verification — 2026-10-15

Environment: Windows development host, Docker Desktop PostgreSQL 17.6, local Next.js production server. Linux Node 22.20 container clean install/build also verified. Synthetic roster only; test JWT cookies are generated by fixtures, not a production login bypass.

## Observed checks

- Unit and legacy regression: 51 tests pass; the original 43 tests are retained.
- Pure core/scoring/policy/pairing coverage: 91.72% statements and 85.58% branches. This coverage scope excludes the UI, HTTP/service and infrastructure scripts; their behavior is exercised separately by integration and browser tests.
- PostgreSQL integration: 12 tests pass, including transactional import, pair ownership, concurrent version conflicts, re-submission/idempotency, staff identity redaction and immutable finalization.
- Playwright: four scenarios repeated three times, 12/12 pass. Landing and mobile evaluation automated axe checks pass. This does not certify full WCAG AA or real Google consent.
- Restricted runtime and restore drill pass: full lifecycle succeeds with the app role; audit update, score deletion and DDL fail. AES-GCM restore preserves all 12 table counts and the final snapshot. Corrupted backups and nonempty target schemas are rejected. Managed schemas are preserved.
- TypeScript, scoped ESLint, OpenAPI validation and production build pass. Production dependency audit reported zero known vulnerabilities at verification time.
- Golden-test fidelity drill passes: a deliberate divisor mutation (5 → 4) causes test failure; the script restores the exact original source and confirms all six focused tests pass. The defective code is never committed.

## Local performance baseline

Run: `npx tsx scripts/test-database.ts perf`. k6 1.3.0, 30 distinct synthetic accounts, 6 groups, 45-second ramp/hold/ramp-down, 0.5-second autosave think time and 1-second submit think time. 588 completed iterations / 1,764 requests, zero HTTP failures. Raw summary: `performance/results/baseline.json`.

- Evaluation data: p95 **53.19 ms** against the 2,000 ms API budget.
- Autosave: p95 **88.06 ms** against 300 ms.
- Submit: p95 **92.55 ms** against 800 ms.

This is an API baseline, not browser page rendering latency. It excludes Internet latency, cold starts, Google OAuth and free-tier contention. It does not prove the PRD's 200-user target or the deployment SLA. Rerun on staging with authorized synthetic data before making cloud performance claims.

Current bottleneck risk: a classroom transaction lock serializes writes. It is deliberately simple and passed the 30-user pilot workload; do not assume that result scales to 200 users. Next improvement should follow measured contention, not remove the integrity lock without an equivalent concurrency design.
